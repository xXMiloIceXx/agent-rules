One entry per task, appended and never rewritten. See `03-iteration.md`.

These were back-filled on 2026-10-02 from the commit history and the comments in `bin/`, each dated

## 2026-09-30 · an index rewrite silently dropped eight rules

- Id: `2026-09-30-an-index-rewrite-silently-dropped-eight-rules`
- Trigger: a rewrite of the entry point dropped the routes for eight rule files in one commit
- Change: added `bin/check-index.mjs`, vendored into every project and run in CI
- Evidence: `node bin/validate-rules.mjs` (check 6), and the guard's own note: "Rewriting an index dropped eight files' routes in one commit and nothing noticed"
- Lesson: a rule nothing routes to is a dead rule. It is still on disk, still in the lock, still passing a per-file hash check — and never read. Reachability has to be checked as its own property, not inferred from the files being present
- Destination: `base:bin/check-index.mjs`
- Promoted: `bin/check-index.mjs` @ 2026-10-02

## 2026-09-30 · a hand-written rule file would have been overwritten

- Id: `2026-09-30-a-hand-written-rule-file-would-have-been-overwritten`
- Trigger: syncing into a project that already had its own `.agents/rules/00-core.md`
- Change: `applySync` now plans the whole set first and aborts before writing anything on a name collision
- Evidence: `git show 21f2c1a --stat`, and the smoke test in `.github/workflows/validate-rules.yml` that asserts a conflict leaves no lock and no sibling file
- Lesson: writing the rest anyway leaves a half-vendored tree whose lock lists only the files that survived, and the guard then reports that tree green. A partial write that passes its own check is worse than a refusal
- Destination: `base:bin/rules-sync.mjs`
- Promoted: `bin/rules-sync.mjs` @ 2026-10-02

## 2026-09-30 · --force could bury the hand-written original

- Id: `2026-09-30-force-could-bury-the-hand-written-original`
- Trigger: `--force` is re-runnable, so a second run could overwrite the `.bak` holding the original file with the base's own previous copy
- Change: the backup is written only when it does not already exist — the first backup wins
- Evidence: `node bin/rules-sync.mjs migrate --into <fixture> --force` twice, then reading `.bak`; asserted in the CI smoke test
- Lesson: "the original is never lost" has to survive the tool being run twice, because the whole point of `--force` is that someone is nervous enough to run it again. A rule that only holds on the first attempt is not a guarantee
- Destination: `base:bin/rules-sync.mjs`
- Promoted: `bin/rules-sync.mjs` @ 2026-10-02

## 2026-09-30 · the GENERATED marker named a command that cannot run

- Id: `2026-09-30-the-generated-marker-named-a-command-that-cannot-run`
- Trigger: the vendored copy of `rules-sync.mjs` can only `check`, but its own header told the reader to run `sync`
- Change: `stampJs`/`stampMarkdown` now say what the vendored copy can actually do, and `sync`/`init`/`migrate` refuse to run from a vendored copy
- Evidence: `git show 0669132`, and `node .agents/bin/rules-sync.mjs sync` from a vendored copy, which exits 2 with the reason
- Lesson: an instruction embedded in generated output is followed. A marker that names the wrong command is not cosmetic — it sends the reader to a command that will fail or, worse, to the wrong repository
- Destination: `base:bin/rules-sync.mjs`
- Promoted: `bin/rules-sync.mjs` @ 2026-10-02

## 2026-09-30 · stamping the repository revision rewrote every vendored file

- Id: `2026-09-30-stamping-the-repository-revision-rewrote-every-vendored-file`
- Trigger: every unrelated commit in the base produced a diff in every consuming project, because the GENERATED stamp carried the repository revision
- Change: the stamp carries a content id (`sha256` of the file, first 12 chars), so it changes only when that file changes
- Evidence: `git show cfc0886`, and the smoke test that runs `init` then `sync` and expects the second to be a no-op
- Lesson: a stamp is an interface. Naming the wrong thing in it turns a no-op sync into a diff in every project at once, and the noise is what makes people stop reading sync output
- Destination: `base:bin/rules-sync.mjs`
- Promoted: `bin/rules-sync.mjs` @ 2026-10-02
