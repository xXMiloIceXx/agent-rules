## 2026-10-02 · excluding a tracked path hides nothing

- Id: `2026-10-02-excluding-a-tracked-path-hides-nothing`
- Trigger: a repository whose rules are written by another tool asked for a mode where the rules are never pushed. The only implementation was 25 lines inside `bin/setup.mjs` that appended `.agents/`, `AGENTS.md` and the CI workflow to `.git/info/exclude`
- Change: `rules-sync local` became a command of its own: it writes only into paths git does not track, hides them through a delimited block in `.git/info/exclude`, refuses when a path it must hide is already tracked, and verifies the result by asking git what it can still see
- Evidence: on a fixture whose `AGENTS.md` was already committed, `git ls-files --error-unmatch AGENTS.md` still lists it after the exclude was written — an ignore rule does not apply to a tracked file
- Lesson: "do not upload this" is a claim about git, so it has to be checked against git rather than expressed as intent. The old code hid a path that was already tracked, reported success, and the very next push published exactly what it promised to hide. A no-op that reports success is worse than a refusal, because it is believed
- Destination: `base:bin/rules-sync.mjs`
- Promoted: `bin/rules-sync.mjs` @ 2026-10-02

## 2026-10-02 · the tool's own advice destroyed another tool's file

- Id: `2026-10-02-the-tools-own-advice-destroyed-another-tools-file`
- Trigger: `migrate` reported a Laravel Boost `CLAUDE.md` as `STALE` and printed `--point-at-index CLAUDE.md --force` as the fix
- Change: a foreign registry now classifies files another tool owns — Boost's `<laravel-boost-guidelines>` marker and `.ai/` tree among them — reports them as `THEIRS` rather than stale, and writes none of them. The recommendation to replace a foreign entry point was removed
- Evidence: running the printed command on a Boost-shaped fixture left the live `CLAUDE.md` as a pointer, with the guidelines the agent actually reads only in a `.bak`: `Select-String -Path CLAUDE.md -Pattern 'Laravel 12, PHP 8.3'` no longer matched
- Lesson: a tool that reports a file as stale is telling the reader to take it over. `STALE` on every run is not a harmless warning — it is an instruction, and it destroyed a file the user never asked us to touch. Worse, Boost would have re-appended its block on the next update, leaving two writers alternating on one file
- Destination: `base:bin/rules-sync.mjs`
- Promoted: `bin/rules-sync.mjs` @ 2026-10-02

## 2026-10-02 · the journal was reported as a dead rule and then retired

- Id: `2026-10-02-the-journal-was-reported-as-a-dead-rule-and-then-retired`
- Trigger: adding `.agents/journal/` to a project before the guards knew about it
- Change: `check-index.mjs` skips the journal like skills and legacy material and reports it separately; `rules-sync` never treats it as legacy material for `--retire`
- Evidence: `node .agents/bin/check-index.mjs` printed `DEAD .agents/journal/2026-10.md — nothing routes to it` and exited 1; `migrate --retire --dry-run` printed `would retire into .agents/legacy/`
- Lesson: a new directory under `.agents/` is not inert. Both guards walk that tree and each one reads an unexpected file as a defect — one fails the build, the other moves the file. Anything stored there has to be excluded from both by name, in the same change that introduces it
- Destination: `base:bin/check-index.mjs`
- Promoted: `bin/check-index.mjs` @ 2026-10-02

## 2026-10-02 · the smoke tests could only be run by pushing

- Id: `2026-10-02-the-smoke-tests-could-only-be-run-by-pushing`
- Trigger: the new smoke tests were written inline in the CI workflow, so the only way to run them was to push
- Change: they moved to tests/smoke.sh, which the workflow now calls; validate-rules check 11 fails if CI stops running that file
- Evidence: `bash tests/smoke.sh` — two bugs surfaced on the first local run, both in the tests: `$(mktemp)` without `-d` returns a file, and a backup copy placed inside the fixture made the "git sees nothing of ours" assertion fail for the wrong reason
- Lesson: an assertion that can only be run by pushing is written once and trusted forever. Both failures were in the test rather than the product, and neither was visible by reading the YAML
- Destination: `base:tests/smoke.sh`
- Direction: the same argument applies to any check that lives only in workflow YAML
- Promoted: `tests/smoke.sh` @ 2026-10-02
